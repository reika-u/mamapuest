# チーム設計 — 人間ひとりで6つの役割を回す

記録日: 2026-09-16

---

## 1. 前提

**人間は1人。** それ以外の役割はAIエージェントに持たせる。

必要な役割:

| 役割 | 担当 |
| --- | --- |
| 経理 | AI（記帳・整理）＋ **税理士**（税務判断） |
| 分析 | AI |
| SNS・マーケ | AI（案出し）＋ **本人**（最終判断・発信） |
| 事務 | AI |
| タスク管理 | AI |
| 法律関係 | AI（論点整理）＋ **弁護士**（判断） |

### 設計の中心にある考え方

> **AIは「下ごしらえ」まで。判断と責任は、本人か有資格者が持つ。**

この事業は法規制が多い領域（特商法・景表法・薬機法・弁護士法・税理士法）を扱う。
AIに判断させると、その一線を越えてしまう。だから各エージェントに
**「ここから先はやらない」を明示的に書き込んである。**

---

## 2. 資格が必要な領域の線引き（最重要）

### 税理士の独占業務（税理士法）

| 区分 | 内容 | AIに任せてよいか |
| --- | --- | --- |
| **税務代理** | 税務署への手続きを代理・代行 | ❌ 税理士のみ |
| **税務書類の作成** | 申告書・申請書を代わりに作成 | ❌ 税理士のみ |
| **税務相談** | 申告書作成等の税務相談に応じる | ❌ 税理士のみ |
| 記帳・会計入力 | 日々の取引を帳簿につける、領収書の仕訳、資料整理 | ⭕ 独占業務ではない |
| 試算表・財務諸表の作成 | 税務書類ではない会計帳簿類 | ⭕ 独占業務ではない |

> 違反すると **2年以下の懲役または100万円以下の罰金**。**無報酬でも罰則の対象**。

→ **経理AIは「記帳・整理・税理士に渡す資料の準備」まで。税額や申告の判断はしない。**

### 弁護士の独占業務（弁護士法72条）

→ 法務AIは**論点の洗い出しと、弁護士に聞くべき質問の整理**まで。法的判断はしない。
詳細は [05-スポンサー型モデル.md](05-スポンサー型モデル.md)。

### 離婚系を扱うことの意味（当面の方針）

**方針: 法務はいずれ人を雇用する。それまではネットで調べてできる範囲でやる。**

この方針自体は成立します。**一般的な情報を提供することは、誰がやっても適法**だからです。
問題になるのは「個別の事案に踏み込んだとき」だけ。境目はここです。

| ⭕ 調べて発信できる（一般情報） | ❌ 有資格者でないとできない |
| --- | --- |
| 公正証書とは何か、作ると何ができるか | この人は公正証書を作るべきか |
| 養育費の相場の一般的な考え方、算定表の存在 | この人はいくら請求できるか |
| 離婚手続きの一般的な流れ | このケースでどう進めるべきか |
| 制度・窓口・専門家の紹介 | 相手方との交渉、書面の作成代行 |

離婚系は**非弁行為の線が最もシビアな領域**です。そのため運用ルールを3つ決めます。

1. **迷ったら「個別」側だと判断して止まる。** 止まったうえで質問リストに入れる
2. **「大丈夫です」と言わない。** 相談者にも、AIにも言わせない
3. **出典を必ず示し、「これは一般的な情報であり法的助言ではありません」を添える**

雇用より前に、**スポット相談できる弁護士を1人確保する**ことを優先してください。
雇用は先でも、「線を越えていないか」を年に数回チェックしてもらう体制は早く要ります。

### そのほか

- 薬機法・景表法の表示判断 → AIは**チェックリストで拾う**が、最終判断は専門家
- 「稼げる」訴求の可否 → 同上

## 3. 6つのエージェント

`.claude/agents/` に定義済み。Claude Code から名前で呼び出せる。

| エージェント | 呼び方 | やること | やらないこと |
| --- | --- | --- | --- |
| **経理** | `keiri` | 記帳、経費の分類、月次のお金の流れの把握、確定申告に持っていく資料の準備 | 税額の計算・判断、申告書の作成、税務相談 |
| **分析** | `bunseki` | Instagram・LINE・講座の数字を読む、KPIの推移、次に何を試すかの提案 | 数字のねつ造、根拠のない断定 |
| **マーケ** | `marketing` | 投稿案・LP・導線の設計、ペルソナに刺さる言葉選び | 薬機法・景表法に触れる表現、誇大な収入訴求 |
| **事務** | `jimu` | メール・文書の下書き、議事録、資料整理、テンプレート作成 | 本人名義での送信判断 |
| **タスク管理** | `task` | タスクの棚卸しと優先順位づけ、[04-タスクリスト.md](04-タスクリスト.md) の更新、進捗の可視化 | 勝手なタスクの削除 |
| **法務リサーチ** | `homu` | 公開情報の調査、一般情報コンテンツのたたき台、弁護士に聞くべき質問リスト、規約のたたき台 | 個別事案への回答、法的判断、「大丈夫です」 |

### 共通ルール（全エージェントに書き込み済み）

1. 判断が必要な場面では**選択肢と推奨を出し、決めるのは本人**
2. **分からないことを分かったふりで埋めない**
3. 有資格者の領域に入ったら**止まって、専門家に聞くべき質問を作る**
4. シングルマザーを孤立させる方向の施策は提案しない（事業理念）
5. 数字は出典を示す。推測なら推測と書く

## 4. ひとりで回すための運用リズム

AIチームがあっても、**本人の時間が最大の制約**。回す型を決めておく。

### 週次（30分）

1. `task` に今週の棚卸しをさせる → 優先3つを決める
2. `bunseki` に先週の数字を見せる → 変化があった点だけ報告させる
3. 個別相談・オプチャで拾った声を1つメモする

### 月次（1〜2時間）

1. `keiri` に月次のお金の流れをまとめさせる
2. `bunseki` に月次レポートを作らせる
3. `task` にタスクリスト全体を更新させる
4. 溜まった法務の疑問を `homu` に整理させ、**四半期に1回まとめて専門家に聞く**

### 発信のたび

- `marketing` に案を出させる → **薬機法・景表法チェックを必ず通す** → 本人が最終判断して投稿

> **専門家への相談はまとめて。** 疑問が出るたびに聞くと費用も時間もかさむ。
> `homu` に質問リストを溜めさせておき、四半期ごとに1回の相談で消化する。

## 5. いつ「人間」を増やすか

AIで代替できない、または代替すべきでない役割から先に人を入れる。

| 順番 | 役割 | 入れるタイミング | 理由 |
| --- | --- | --- | --- |
| 1 | **税理士** | 収入が発生したらすぐ | 独占業務。AIでは代替不可 |
| 2 | **弁護士**（スポット→顧問→雇用） | 報酬設計を固める前 | 同上。離婚系を扱うため線引きの確認が要る |
| 3 | **個別相談の対応者** | 相談が週5件を超えたら | 自分の消耗が事業のボトルネックになる |
| 4 | オプチャの見守り | 参加者が増えたら | 荒れると理念そのものが壊れる |
| 5 | 事務・経理の実務 | 講座運営が回り始めたら | AIで粘れる領域。最後でよい |

→ 探し方は [03-専門家の探し方.md](03-専門家の探し方.md)。

---

## 6. 注意していること

- **AIに「大丈夫です」と言わせない。** この事業で一番怖いのは、法的にグレーなものを
  AIが「問題ありません」と言い、それを信じて進めてしまうこと。各エージェントには
  判断を保留して専門家に繋ぐよう指示してある
- **AIが出したものをそのまま外に出さない。** 特に発信文・規約・相談者への返信
- **相談者の個人情報をAIに投げない。** 名前・住所・具体的な事案はマスクする
- **離婚系は特に慎重に。** 一般情報の提供にとどめ、個別事案に踏み込まない。
  判断に迷ったものは `homu` に質問リストとして溜め、まとめて弁護士に確認する
