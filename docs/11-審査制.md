# 審査制の設計

記録日: 2026-09-18 / 出典: 音声メモ（第7回）

> **決定: 無料にしろ、数千円取るにしろ、審査制にする。**

---

## 1. 審査制が効く理由

価格とは別のレイヤーで、4つ同時に効きます。

| 効果 | 中身 |
| --- | --- |
| **コミットメント** | 応募フォームを書く＝時間の投資。書いた時点で当事者になる |
| **選別** | 冷やかしが減る。無料でも本気の人が残る |
| **特別感** | 「選ばれて入った」は継続率に効く。誰でも入れる場は大事にされない |
| **運営の防衛** | トラブルになる人、勧誘目的の人を最初から入れない |

4つ目が実務的には大きい。**ひとりで運営する以上、入口で防ぐのが唯一の防衛策**です。

### デポジットとの併用

審査制とデポジット（[10-価格設計.md](10-価格設計.md)）は**役割が違うので併用できます**。

- 審査 = 入る**前**のフィルター（誰を入れるか）
- デポジット = 入った**後**の推進力（続ける理由）

## 2. 🔴 何を審査するか — 能力ではなく「状態」

**A層は「始める前に挫けている」層です。能力で審査するのは無意味かつ残酷。**

見るのは、**今このタイミングで動ける状態にあるか**だけ。

| 見ること | なぜ |
| --- | --- |
| **7日間、1日15分を確保できるか** | 物理的に不可能なら、参加しても傷つくだけ |
| 目的が一言でも言語化できているか | 完璧でなくていい。「お金がほしい」でも十分 |
| コミュニティのルールに同意できるか | 勧誘禁止・誹謗中傷禁止など |
| **今、危機的な状況にないか** | 後述。最重要 |

### 見ないこと

- スキル、経験、学歴
- パソコンを持っているか（スマホ前提で設計する）
- 熱意の大きさ（熱意が高い人ほど燃え尽きることもある）

## 2.5 除外基準（2026-09-18 メモ）

> **指示: 生活保護を受けている人、借金がある人はNG。**

意図は理解できます。**どちらも「参加しても本人が損をする／トラブルになる」ことを
避けるための、守りの基準**です。その意図は正しい。

ただし調べた結果、**このままの形だと事実関係と実務の両面で問題が出ます。**
以下を確認したうえで、最終的な線引きを決めてください。

### ① 生活保護について — 事実確認

| 論点 | 調べた結果 |
| --- | --- |
| 受給中の就労・副業は禁止か | **禁止されていない。** 受給の条件は「収入が最低生活費より少ないこと」であり、働いているかは関係ない |
| 生活保護制度の目的 | **自立の助長**を含む。就労は制度が想定している方向 |
| 稼いだら全部引かれるのか | **引かれない。勤労控除がある。** 月8,000円までの勤労収入は全額控除。基礎控除は1級地で月33,190円が上限 |
| 申告は必要か | **必要。全額申告義務がある。** 無申告は不正受給となり、返還請求や罰則の対象 |

つまり **「稼いでも意味がない」は不正確**で、正しく申告すれば手元に残ります。

### ⚠️ 除外した場合に起きること

1. **理念との衝突**
   経済的自立を支援する事業が、**最も経済的に困っている層を排除する**構図になります。

2. **スポンサー・助成金の審査で必ず問われる**（[05-スポンサー型モデル.md](05-スポンサー型モデル.md)）
   助成財団や企業CSRは「誰を支援するのか」を見ます。
   募集要項に「生活保護の方はご遠慮ください」と書いてあると、**ほぼ確実に論点になります**。

3. **公開すると印象が悪い**
   内部の運用基準として持つのと、募集要項に書くのとでは意味が違います。

### 💡 代案：除外ではなく「条件付き」にする

意図（本人が損をしない・トラブルにしない）は、**条件を付ければ達成できます。**

> **「生活保護を受給中の方は、事前に担当のケースワーカーに相談のうえご応募ください。
> 収入は全額申告が必要です」**

- 本人の不利益（不正受給リスク）を防げる
- 排除ではないので理念とも助成金審査とも衝突しない
- ケースワーカーに相談できない状態の人は、自然に応募してこない（実質的なフィルターになる）
- 有料商品の案内は控え、**無料リソースを中心に案内する**という運用も併用できる

### ② 借金について — 定義が広すぎる

「借金がある人」を文字通り適用すると、**奨学金・住宅ローン・車のローン・分割払い・リボ**が
すべて含まれます。シングルマザーの多くが何らかの借入を持っているため、
**対象者がほとんどいなくなります。**

本当に避けたいのは、借入の有無ではなく **状態**のはずです。

| 避けたい状態 | 見分け方 |
| --- | --- |
| **借りてまで参加費を払う** | 直接聞ける。同意事項にできる |
| 返済に追われ、短期で成果を出さないといけない | 「いつまでにいくら必要か」を聞けば分かる |
| 多重債務で判断が歪んでいる | トリアージ対象。排除ではなく専門窓口へ |

### 💡 代案：行動基準に変える

応募フォームの同意事項として、次を置く。

> - **借入をして参加費を支払わないこと**
> - **返済のために短期間で収入を作る目的での参加はご遠慮ください**
>   （この企画は、初めての報酬を得ることを目的としています）

さらに、多重債務の兆候がある人は**排除せず、窓口へ回す**（トリアージと同じ発想）。

- 法テラス（債務整理の無料相談）
- 消費生活センター（188）

### ③ 運用上の限界

どちらの基準も、**自己申告でしか確認できません。**
信用情報を取ることはできませんし、取ろうとすれば法的な問題になります。

→ だからこそ「**審査基準**」として持つより「**同意事項**」として置く方が実効性があります。
同意した記録が残るので、トラブル時の根拠にもなります。

### まとめ：推奨する形

| 当初の指示 | 推奨する形 |
| --- | --- |
| 生活保護はNG | **条件付き可**（ケースワーカーへの事前相談＋申告義務の明示）。有料商品は控える |
| 借金がある人はNG | **同意事項に変換**（借入をして参加費を払わない／返済目的の短期収入狙いは対象外） |
| — | 多重債務・生活困窮の兆候 → **トリアージで窓口へ** |

> **この推奨を採らず、当初の指示どおり除外する判断も当然ありえます。**
> その場合は、**募集要項には書かず、内部の運用基準として持つ**ことを強く勧めます。
> 公開すると、理念と助成金獲得の両方に影響します。

## 3. 🚨 審査は「トリアージ」でもある

応募者の中に、**今はチャレンジではなく相談窓口が必要な人**がいます。

- DVの渦中にいる
- 精神的に限界が近い
- 今日明日の生活費がない

こうした人に7日間のチャレンジを渡すのは、助けにならないどころか有害です。

> **この人たちは「落とす」のではなく「適切な場所へ回す」。**

- 公的窓口を案内する（DV相談＋ 0120-279-889 など。[06-シンママbot.md](06-シンママbot.md)）
- シンママbotの手当診断・無料情報へ繋ぐ
- 「状況が落ち着いたら、次の期に優先してご案内します」と伝える

**審査フォームに、それを拾う設問を1つ入れておく。** 例:

> 「今、緊急で困っていることはありますか？（あれば選んでください／任意）」
> □ 生活費 □ 住まい □ 安全（DV等） □ 心身の不調 □ 特にない

チェックが入った人には、選考結果とは別に**必ず窓口情報を届ける**。

## 4. ⚠️ 落とし方の設計 — ここが一番繊細

### リスク

**A層は「また自分はダメだった」を積み重ねてきた層です。**
落選体験が、その積み重ねをもう一段深くする可能性があります。
ここを雑にやると、**理念そのものを裏切る**ことになる。

### 原則

| ⭕ やる | ❌ やらない |
| --- | --- |
| 「今回はご縁がなかった」という伝え方 | 「不合格」「基準に達しませんでした」 |
| **全員に何かを渡して終わる**（無料リソース・bot案内） | 落選通知だけ送って終わり |
| 「次の期に優先してご案内します」と道を示す | 二度と連絡しない |
| 落選理由は個別に伝えない（定型文） | 個別に理由を説明する ※トラブルの元 |
| **落選者もリストには残す** | リストから外す |

### 落選者こそ資産

- 落選＝「今じゃない」だけ。次の期、あるいはコンテンツ販売の顧客になりうる
- 無料リソース（bot、情報発信）は使い続けてもらう
- ここを丁寧にやるかどうかが、長期の評判を決めます

## 5. 応募フォームの設計

**フォームそのものが3つの仕事をします。** 審査・セグメント分け・商品設計データ。

### 設問案（たたき台）

| # | 設問 | 目的 |
| --- | --- | --- |
| 1 | 副業をやってみたことはありますか？（ある/ない） | **A層/B層の分岐**（[09](09-収益モデル.md)） |
| 2 | （「ある」の人へ）どこで止まりましたか？（選択式） | **コンテンツ販売の商品設計データ** |
| 3 | 1日15分、7日間の時間を確保できそうですか？ | 審査の中心 |
| 4 | 参加して、どうなりたいですか？（一言でOK） | 言語化の確認・当事者化 |
| 5 | 今、緊急で困っていることはありますか？（任意） | **トリアージ** |
| 6 | ルールへの同意（勧誘禁止・誹謗中傷禁止／**借入をして参加費を払わない** 等） | 運営の防衛 |

> 生活保護の受給有無を設問にするかは要検討（2.5 参照）。
> 聞くなら「除外のため」ではなく「**ケースワーカーへの相談をご案内するため**」という位置づけに。

### 設計のポイント

- **設問は6問以内。** 多いと離脱する（A層は特に）
- 自由記述は**1問だけ**、「一言でOK」と書く
- 本名は不要（ニックネーム可）
- 「書くのが大変」と感じさせない。ただし**ゼロ手間にはしない**（それがコミットメント）

## 6. 運用 — 自分の時間を守る

**審査は自分の時間を食います。** ここを設計しないと、人数を増やせません。

- **合否基準を先に文章化しておく**（毎回悩まない）
- 定型の合格通知・不合格通知を**先に作っておく**
- 判断に迷う人は「合格」に寄せる（落とすコストの方が高い）
- **1期の定員を決める**（型ができるまでは小さく。[08](08-ターゲット設計.md)）
- 応募多数なら、**先着ではなく次期優先案内**で捌く

### 定員を設ける場合の注意

「定員◯名」と書くなら、**実際にその人数で締め切ること**。
実態のない限定表示は有利誤認のリスクがあります（[09](09-収益モデル.md)）。

## 7. 法務チェック

- [ ] 🔴 応募フォームで**個人情報の利用目的を明示**する（個人情報保護法）
- [ ] 🔴 落選者のデータをどう扱うかを決め、フォームに書く
      （リストに残すなら、その旨を明示して同意を得る）
- [ ] 🟡 審査基準に差別的な要素を入れない
- [ ] 🟡 「定員◯名」と書くなら実際にその人数で締め切る（有利誤認の回避）
- [ ] 🟡 緊急性のある応募者への窓口案内フローを作る（[06](06-シンママbot.md)）
- [ ] 🟡 ルール同意の記録を残す（トラブル時の根拠）
- [ ] 🔴 除外基準を募集要項に書くか、内部基準に留めるかを決める（2.5 参照）
- [ ] 🟡 生活保護の受給状況を聞く場合、利用目的を明示する（機微な情報にあたる）

## 8. 測る指標

| 指標 | 見る理由 |
| --- | --- |
| 応募数 / 合格数 / 辞退数 | 入口の実態 |
| **合格者の完走率 vs 無審査だった場合の想定** | 審査が効いているかの検証 |
| フォームの離脱率（開いたが送信しなかった） | 設問が重すぎないか |
| 落選者のLINE残存率 | 落とし方が丁寧にできているか |
| **次期への落選者の再応募率** | 「また来てくれる」落とし方ができたか |
| 審査にかかった自分の時間（1人あたり） | スケールできるか |
