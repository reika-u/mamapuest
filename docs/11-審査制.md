# 審査制の設計

記録日: 2026-09-18 / 出典: 音声メモ（第7回）

> **決定: 無料にしろ、数千円取るにしろ、審査制にする。**

---

## 1. 審査制が効く理由

価格とは別のレイヤーで、4つ同時に効きます。

| 効果 | 中身 |
| --- | --- |
| **コミットメント** | 応募フォームを書く＝時間の投資。書いた時点で当事者になる |
| **選別** | 冷やかしが減る。無料でも本気の人が残る |
| **特別感** | 「選ばれて入った」は継続率に効く。誰でも入れる場は大事にされない |
| **運営の防衛** | トラブルになる人、勧誘目的の人を最初から入れない |

4つ目が実務的には大きい。**ひとりで運営する以上、入口で防ぐのが唯一の防衛策**です。

### デポジットとの併用

審査制とデポジット（[10-価格設計.md](10-価格設計.md)）は**役割が違うので併用できます**。

- 審査 = 入る**前**のフィルター（誰を入れるか）
- デポジット = 入った**後**の推進力（続ける理由）

---

## 2. 🔴 何を審査するか — 能力ではなく「状態」

**A層は「始める前に挫けている」層です。能力で審査するのは無意味かつ残酷。**

見るのは、**今このタイミングで動ける状態にあるか**だけ。

| 見ること | なぜ |
| --- | --- |
| **7日間、1日15分を確保できるか** | 物理的に不可能なら、参加しても傷つくだけ |
| 目的が一言でも言語化できているか | 完璧でなくていい。「お金がほしい」でも十分 |
| コミュニティのルールに同意できるか | 勧誘禁止・誹謗中傷禁止など |
| **今、危機的な状況にないか** | 後述。最重要 |

### 見ないこと

- スキル、経験、学歴
- パソコンを持っているか（スマホ前提で設計する）
- 熱意の大きさ（熱意が高い人ほど燃え尽きることもある）

---

## 3. 🚨 審査は「トリアージ」でもある

応募者の中に、**今はチャレンジではなく相談窓口が必要な人**がいます。

- DVの渦中にいる
- 精神的に限界が近い
- 今日明日の生活費がない

こうした人に7日間のチャレンジを渡すのは、助けにならないどころか有害です。

> **この人たちは「落とす」のではなく「適切な場所へ回す」。**

- 公的窓口を案内する（DV相談＋ 0120-279-889 など。[06-シンママbot.md](06-シンママbot.md)）
- シンママbotの手当診断・無料情報へ繋ぐ
- 「状況が落ち着いたら、次の期に優先してご案内します」と伝える

**審査フォームに、それを拾う設問を1つ入れておく。** 例:

> 「今、緊急で困っていることはありますか？（あれば選んでください／任意）」
> □ 生活費 □ 住まい □ 安全（DV等） □ 心身の不調 □ 特にない

チェックが入った人には、選考結果とは別に**必ず窓口情報を届ける**。

## 4. ⚠️ 落とし方の設計 — ここが一番繊細

### リスク

**A層は「また自分はダメだった」を積み重ねてきた層です。**
落選体験が、その積み重ねをもう一段深くする可能性があります。
ここを雑にやると、**理念そのものを裏切る**ことになる。

### 原則

| ⭕ やる | ❌ やらない |
| --- | --- |
| 「今回はご縁がなかった」という伝え方 | 「不合格」「基準に達しませんでした」 |
| **全員に何かを渡して終わる**（無料リソース・bot案内） | 落選通知だけ送って終わり |
| 「次の期に優先してご案内します」と道を示す | 二度と連絡しない |
| 落選理由は個別に伝えない（定型文） | 個別に理由を説明する ※トラブルの元 |
| **落選者もリストには残す** | リストから外す |

### 落選者こそ資産

- 落選＝「今じゃない」だけ。次の期、あるいはコンテンツ販売の顧客になりうる
- 無料リソース（bot、情報発信）は使い続けてもらう
- ここを丁寧にやるかどうかが、長期の評判を決めます

## 5. 応募フォームの設計

**フォームそのものが3つの仕事をします。** 審査・セグメント分け・商品設計データ。

### 設問案（たたき台）

| # | 設問 | 目的 |
| --- | --- | --- |
| 1 | 副業をやってみたことはありますか？（ある/ない） | **A層/B層の分岐**（[09](09-収益モデル.md)） |
| 2 | （「ある」の人へ）どこで止まりましたか？（選択式） | **コンテンツ販売の商品設計データ** |
| 3 | 1日15分、7日間の時間を確保できそうですか？ | 審査の中心 |
| 4 | 参加して、どうなりたいですか？（一言でOK） | 言語化の確認・当事者化 |
| 5 | 今、緊急で困っていることはありますか？（任意） | **トリアージ** |
| 6 | ルールへの同意（勧誘禁止・誹謗中傷禁止 等） | 運営の防衛 |

### 設計のポイント

- **設問は6問以内。** 多いと離脱する（A層は特に）
- 自由記述は**1問だけ**、「一言でOK」と書く
- 本名は不要（ニックネーム可）
- 「書くのが大変」と感じさせない。ただし**ゼロ手間にはしない**（それがコミットメント）

## 6. 運用 — 自分の時間を守る

**審査は自分の時間を食います。** ここを設計しないと、人数を増やせません。

- **合否基準を先に文章化しておく**（毎回悩まない）
- 定型の合格通知・不合格通知を**先に作っておく**
- 判断に迷う人は「合格」に寄せる（落とすコストの方が高い）
- **1期の定員を決める**（型ができるまでは小さく。[08](08-ターゲット設計.md)）
- 応募多数なら、**先着ではなく次期優先案内**で捌く

### 定員を設ける場合の注意

「定員◯名」と書くなら、**実際にその人数で締め切ること**。
実態のない限定表示は有利誤認のリスクがあります（[09](09-収益モデル.md)）。

## 7. 法務チェック

- [ ] 🔴 応募フォームで**個人情報の利用目的を明示**する（個人情報保護法）
- [ ] 🔴 落選者のデータをどう扱うかを決め、フォームに書く
      （リストに残すなら、その旨を明示して同意を得る）
- [ ] 🟡 審査基準に差別的な要素を入れない
- [ ] 🟡 「定員◯名」と書くなら実際にその人数で締め切る（有利誤認の回避）
- [ ] 🟡 緊急性のある応募者への窓口案内フローを作る（[06](06-シンママbot.md)）
- [ ] 🟡 ルール同意の記録を残す（トラブル時の根拠）

## 8. 測る指標

| 指標 | 見る理由 |
| --- | --- |
| 応募数 / 合格数 / 辞退数 | 入口の実態 |
| **合格者の完走率 vs 無審査だった場合の想定** | 審査が効いているかの検証 |
| フォームの離脱率（開いたが送信しなかった） | 設問が重すぎないか |
| 落選者のLINE残存率 | 落とし方が丁寧にできているか |
| **次期への落選者の再応募率** | 「また来てくれる」落とし方ができたか |
| 審査にかかった自分の時間（1人あたり） | スケールできるか |
