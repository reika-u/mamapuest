## 1. SNSマーケティング部の位置づけ

### 1.1 何をする部か

この部は、事業の集客とファン化の起点である **Instagram** を中心に、以下を作る。

- Instagram の投稿案（リール構成・フィード・ストーリーズ導線）
- LINE公式アカウントの配信文・リッチメニュー文言
- LP・申込フォームの文言
- 無料（0→1企画・シンママbot）→ 個別相談／オープンチャット → 講座、の集客導線設計

土台となるターゲット設計は [08-ターゲット設計.md](08-ターゲット設計.md)。
**最初はA層（何から始めればいいか分からない人）に発信を振り切る**方針に沿って、
本ドキュメントのリサーチ・ネタ帳もA層向けに寄せてある。

### 1.2 `marketing` エージェントとの関係

[07-チーム設計.md](07-チーム設計.md) で定義済みの `marketing` エージェント（`.claude/agents/marketing.md`）が、
このSNSマーケティング部の**実行担当**にあたる。関係は次の通り。

| | 役割 |
| --- | --- |
| 本ドキュメント（部の運用マニュアル） | 市場リサーチの蓄積、ネタ帳、発信の型（何を・どのフォーマットで・なぜ）の置き場 |
| `marketing` エージェント | 本ドキュメントとペルソナ設計（08）をもとに、都度の投稿案・配信文をそのまま投稿できる形で出す実行係 |

`marketing` を呼ぶたびに、本ドキュメントの「3. ネタ帳」から狙いに合うものを起点にすると、
毎回ゼロから発想し直さずに済む。ネタ帳が尽きたら、このドキュメントに追記していく。

### 1.3 意思決定の原則

[07-チーム設計.md](07-チーム設計.md) の共通ルールをそのまま適用する。

1. **AI（このドキュメント作成作業も含む）は案出し・リサーチまで。投稿するかどうかの最終判断は代表本人。**
2. 分からないことを分かったふりで埋めない。数字は出典を示す。推測は推測と書く。
3. 薬機法・景表法・誇大な収入訴求に触れる可能性がある表現は、断定せず「専門家確認」を明記する。
4. シングルマザーを孤立させる方向の訴求（競争を煽る、他人と比べさせる）はしない。
5. 相談の場での売り込みはしない（相談と販売は分ける）。

#### ⚠️ 「ひとりで回す」原則との緊張関係

→ この緊張関係を踏まえ、**「5つとも将来的にはやるが、今は1つずつ本気で立ち上げる」**という方針で確定した（上記の着手順）。
立ち上げ済みでないアカウントは、投稿を無理に作らず休止扱いにしてよい。**軽い頻度で"薄く"維持する運用は、
本気で回すアカウント数を実質的に増やすだけなので推奨しない。**

- 次のアカウントに着手するタイミングの目安: 今のアカウントの運用リズムが安定してから（07の週次・月次リズムが回るようになった頃）

### 2.2 「怪しい副業アカウント」との混同リスクと、そこにある差別化ポイント

**分かったこと**: 主婦・副業ジャンルでは「怪しいインスタ副業」への注意喚起記事が多数存在し、以下が典型的な見分け方として繰り返し紹介されている。

- 「〇〇ママ」「主婦の〇〇」を名乗り親近感を作ったうえで、高額講座（数十万円）へ誘導する
- 成果が出る前に「教材費」「登録料」など先にお金を払わせる
- 運営会社名・特定商取引法の表記が確認できない

### 2.4 「0→1（初報酬）」「7日間チャレンジ」型の先行事例

**分かったこと**:
- セルフバック（自己アフィリエイト）は、副業初心者向けメディア・ASP公式ブログで広く紹介される「無料またはリスク低く報酬を得る」代表的な手法。クレジットカード発行や証券口座開設などで数千円〜数万円の報酬が得られる案件がある

#### 5.1.2 「体験談を募集して公開する」運用フロー（先行事例からの示唆）

**分かったこと**:
- 取材・掲載にあたっては「取材・掲載同意書」（氏名・発言・写真等の使用範囲について書面で合意を取る文書）を用意するのが一般的な実務とされる
- 同意書には「匿名での利用」「個人が特定されない形での集計・公表」といった条件を盛り込むことで、対象者のプライバシーを保護する運用が紹介されている
- 個人情報保護法の観点からは、収集・利用・保管・第三者提供の範囲を明記し「利用目的の明示」と「本人同意」を満たすことが求められるとされる
- 体験談を募集して漫画化する個人ブログ・メディアの事例でも、「本人特定になるような文章・表現は控える」ことが注意点として挙げられている

#### 5.1.3 実話漫画にまつわる法的リスクの一般論

**分かったこと**:
- 実在の人物をモデルにした創作物であっても、名前や属性を変えても本人が特定できる状態であれば、名誉毀損・プライバシー侵害・肖像権侵害に該当しうる
- 名誉毀損は「社会的評価の低下」、プライバシー侵害は「私生活上の情報をみだりに公開すること」という異なる要件があり、同時に成立するケースもある
- 過去の裁判例（三島由紀夫『宴のあと』、柳美里『石に泳ぐ魚』等）では、モデルの容姿・国籍・出身大学・家族構成などがそのまま描写されたことがプライバシー侵害・名誉毀損と判断され、出版差し止めに至った例がある

### 5.2 ネタ帳（コンテンツの切り口・フォーマット集）

> **重要**: 以下は**テーマカテゴリと構成の指針のみ**。具体的な実話・エピソード本文はここには書かない。
> 実際の投稿を作る際は、代表本人のエピソード、または募集で得た投稿者のエピソードを元に、
> `marketing` エージェントが個別に構成案を起こす。

#### 実話を扱う上での注意点チェックリスト（投稿前に毎回確認）

投稿・構成案を作る `marketing` エージェント、および最終判断をする代表本人は、以下を**投稿のたびに**確認する。

- [ ] **第三者の特定を避けているか** — 元配偶者・子ども・親族・職場等、本人以外が特定できる情報（実名・勤務先・地域・時期・外見の特徴・SNSアカウント名等）が含まれていないか
- [ ] **誇張していないか** — 実際の出来事の範囲を超えて演出していないか。誇張は名誉毀損・信用毀損リスクを高める（[5.1.3](#513-実話漫画にまつわる法的リスクの一般論)）
- [ ] **「個人の体験談です」の明記があるか** — 一般化・断定表現（「離婚するとみんなこうなる」等）を避け、あくまで一事例であることを明示しているか
- [ ] **本人（投稿者）の同意範囲を超えていないか** — 募集エピソードの場合、同意書に記載した利用目的・公開範囲（匿名化の程度、修正の可否、公開後の削除依頼への対応等）の中に収まっているか（[5.3](#53-法務チェック)）
- [ ] **DV・虐待等、当事者の安全に関わる情報を不用意に晒していないか** — 加害者が投稿を見て当事者を特定・報復するリスクがないか
- [ ] **煽り・恐怖で読ませる作りになっていないか** — 「あなたも同じ目に遭うかも」と不安を煽る構成ではなく、共感・気づき・その先の情報（相談窓口等）につなげる構成になっているか（共通ルール、[07-チーム設計.md](07-チーム設計.md)）
- [ ] **専門的な内容（法律・手当等）を扱う場合、一般情報の範囲に収まっているか** — 「離婚したらこうなる」という一般論と、「あなたはこうすべき」という個別助言を混同していないか（非弁行為の論点。[07-チーム設計.md](07-チーム設計.md) 2章）
- [ ] 迷ったら投稿を保留し、`homu` の質問リストに追加する

### 5.3 法務チェック

[02-法務リスク.md](02-法務リスク.md) のトーンに準拠し、このアカウント特有の論点を**投稿・募集運用の前に確認すべき項目**として整理する。**詳細な法的分析・最終判断は `homu` エージェント経由で弁護士に確認する**（ここでは論点の見取り図のみ）。

| 論点 | 内容 | 確認すべきタイミング |
| --- | --- | --- |
| **名誉毀損・プライバシー侵害** | 元配偶者・子ども・親族等、第三者が特定可能な形で描かれていないか。名前・属性を変えても、外見・経歴・時期等の組み合わせで特定できる場合はリスクが残る（[5.1.3](#513-実話漫画にまつわる法的リスクの一般論)） | **毎投稿前**。専門家確認 |
| **肖像権・著作権** | AI漫画生成ツールの利用規約上、生成物の商用利用・SNS投稿が許諾されているか。学習データ・出力物の権利関係もツールごとに確認が必要 | ツール選定時、専門家確認 |
| **募集エピソードの利用許諾** | 外部から募集したエピソードを漫画化・公開する場合、投稿者からの**利用許諾・二次利用の同意**（公開範囲・修正可否・削除依頼への対応を含む）が必要（[1.4](#新たに生じる法務論点homu-への確認が必要)） | 募集企画の設計時。同意書のたたき台は `homu` が作成し、弁護士確認を通す |
| **同意の撤回・削除依頼への対応** | 公開後に投稿者や第三者から「特定できる」「削除してほしい」等の申し出があった場合の対応フローが未整備 | 募集企画の運用開始前に整備。専門家確認 |
| **未成年（子ども）に関する情報** | 子どものエピソードを扱う場合、個人情報保護法上の配慮に加え、子ども自身の将来（成人後に検索される等）への影響も論点になりうる | 該当エピソードが出るたび。専門家確認 |
| **景表法・優良誤認** | 「相談してよかった」等の体験談を紹介する際、特定の相談先・サービスを暗に宣伝する形になっていないか（[02-法務リスク.md](02-法務リスク.md) 2章のステマ規制と同様の考え方） | 相談先・専門家を紹介する回のたび |
| **一般情報と個別助言の境界** | 手続き・お金の壁系（テーマ8）を扱う際、「一般的な制度説明」を超えて「あなたはこうすべき」という個別助言に踏み込んでいないか（非弁行為の論点、[07-チーム設計.md](07-チーム設計.md) 2章） | 該当テーマを扱うたび |
| **DV・安全配慮** | 加害者が投稿を閲覧できる前提で、当事者・子どもの安全を脅かす具体性（居住エリア、勤務先、通う学校等）が残っていないか | 該当エピソードが出るたび |

> これらはすべて論点の洗い出しであり、法的な結論ではない。判断に迷うものは断定せず、
> `homu` エージェントに「弁護士へ聞くべき質問」として溜め、[07-チーム設計.md](07-チーム設計.md) の運用リズム
> （四半期に1回まとめて専門家に確認）に沿って処理する。**募集企画の本格開始前には、同意書のたたき台と
> 削除依頼への対応フローについて、最低1回は専門家確認を挟むことを強く推奨する。**
